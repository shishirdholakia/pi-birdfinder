ARU dashboard map/override update
=================================

This patch adds a Leaflet satellite map to the dashboard and integrates saved map
location overrides into calibration/localization jobs.

Files changed:
  app.py
  config.yaml
  requirements.txt
  templates/index.html
  static/dashboard.js
  static/styles.css
  aru_pipeline/maps.py

New dashboard endpoints:
  GET    /api/map/locations
  GET    /api/map/location-overrides
  POST   /api/map/location-overrides
  DELETE /api/map/location-overrides
  GET    /api/map/result-layers?kind=calibration|localization

New files written by the dashboard:
  data/location_overrides/active_location_override.txt
  data/location_overrides/active_location_override_enabled.txt

New behavior:
  * The map shows averaged unit locations from the dashboard location summaries.
  * You can create draggable override pins from averages or place a unit pin by clicking the map.
  * Saving pins writes active_location_override.txt in the TXT format accepted by the pipeline.
  * Calibration/localization forms have a checkbox to use saved map overrides if enabled.
  * The dashboard automatically saves unsaved pin edits before starting calibration/localization when that checkbox is checked.
  * Calibration/localization maps generated by aru_pipeline/maps.py now also write a .geojson companion file.
  * The dashboard can draw those GeoJSON result layers on the live Leaflet map. If no GeoJSON exists for older results, it opens the Folium HTML map in the artifact preview.

Install:
  cd /home/shishir/aru-dashboard
  cp -a app.py "app.py.bak.$(date +%Y%m%d_%H%M%S)"
  cp -a static "static.bak.$(date +%Y%m%d_%H%M%S)"
  cp -a templates "templates.bak.$(date +%Y%m%d_%H%M%S)"
  cp -a aru_pipeline "aru_pipeline.bak.$(date +%Y%m%d_%H%M%S)" 2>/dev/null || true

  unzip -o aru_dashboard_map_overrides_update.zip
  source .venv/bin/activate
  python -m pip install -r requirements.txt
  python -m py_compile app.py aru_pipeline/*.py

Restart uvicorn and hard-refresh your browser. The dashboard.js URL is cache-busted,
but a hard refresh is still useful.
